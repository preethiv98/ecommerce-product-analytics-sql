What the data is

Every row is one shopper action in a multi-category online store: a view, a cart add or a purchase. Each carries a timestamp, product, brand, price, user and session, plus a category path like electronics.video.tv.

There is no order ID or customer profile, so I analyzed at the session and category level.

🔎

What I analyzed

  • Revenue by product type and category. Phones & Computing is about 80% of categorized revenue.
  • The funnel from views to carts to purchases, to see where shoppers drop off.
  • Conversion by category: what turns browsing into buying.
  • Top and lowest category within each product type.
  • Average order value in each category.

How it was built

Moving the heavy lifting into SQL keeps the dashboard fast and the logic reproducible.

Clean in SQL

Dot-separated category paths such as furniture.universal.light were converted into readable labels with SPLIT_PART(), INITCAP() and REPLACE().

Aggregate upstream

Events were collapsed into a 7,625-row table of views, carts and purchases per day and category, so Tableau never scans raw logs.

Group and visualize

A category_map table groups about 130 categories into 8 product types, powering the click-to-drill dashboard.

Limitations

Two months of data only, so no seasonality or lifetime value. Orders are approximated by purchase sessions (no order ID), and a session touching several categories is counted in each. Product types are my own grouping, not part of the source data. Data source: Kaggle eCommerce Behavior Data.
